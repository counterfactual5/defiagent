Grounding Context

Codebase Context. 产品是 Next 14 + Tailwind 的 DeFi Agent：左侧项目卡 + 右侧 useChat 对话。现行 UI 在 app/page.tsx 内联完成，浅色 Inter / slate / blue，.glass-panel 实为不透明白卡片。

  • 模式： sticky header + max-w-[1200px] 双栏；移动端侧栏叠在聊天上方。
  • 痛点：components/RepoPanel.tsx（暗色、LIVE_TOOLS、stars/forks）从未被 import；页面自维护另一份 REPOS，与 lib/repos.ts 漂移（如 polymarket-sdk vs polymarket-py）。
  • 工具不可见：/api/chat 在服务端完成 tool 循环后只流式输出清洗后的 Markdown；客户端只有通用 spinner。
  • 品牌未落地：icon.svg 的蓝→紫渐变几乎只出现在 favicon；UI 满屏 flat blue-600。
  • 外部参照：Cursor/Manus 活动面板、Vercel AI SDK generative UI、Phantom/Uniswap 单强调色、Perplexity/Messari 引用、Bankr 终端、Aave Glass/Pro。
  • Past learnings：仓库无 solutions/ / CONCEPTS.md。

Ranked Ideas

按「能否改变下一步决策」排序。建议优先做 #1+#4（立刻变好看且复用现成代码），再上 #2+#3（让 Live Tools 名副其实）。

1. 启用休眠侧栏（Ship the dormant rail）

ID 1 sidebar-rail Confidence 92% Complexity Low

Description: 删除 page.tsx 内联的简化侧栏，挂载（或拆分复用）已存在的 RepoPanel 能力：LIVE_TOOLS 网格、点击建议提示词、经 /api/repos 的 stars/forks。仓库元数据统一走 lib/repos.ts，消灭两套列表漂移。视觉对齐到现行浅色壳，而不是直接套暗色 orphan 主题。

Axis: sidebar-rail

Basis:
direct: RepoPanel.tsx 零引用但含 LIVE_TOOLS + /api/repos；page.tsx 侧栏仅 repos、无 stats；lib/repos.ts 与 page REPOS 列表不一致 external: Aave Pro / Bankr — 侧栏作为能力地图而非静态链接墙

Rationale: Header 写着 “Live Tools”，用户却只看到 GitHub 简介卡——更好的侧栏已经写好却没接上。这是投入产出比最高的「变好看 + 变真」。

Downsides: 需要统一主题 token（RepoPanel 的 .glass 未定义）；合并 demoPrompt / 图标字段时要一次数据模型整理。

示意：把已写好却休眠的能力接到正式壳上，而不是再设计第三套侧栏。

2. 工具活动回执条（Tool activity / receipt rail）

ID 2 tool-transparency Confidence 88% Complexity Medium

Description: 在对话头或输入框上方增加细活动条：工具名、数据源（CoinGecko / DefiLlama / Etherscan）、耗时、成败。最小版可先用阶段标签（Routing → Tool → Synthesize）；完整版通过 AI SDK data stream 推送 tool 事件。把「Agent is thinking and processing tools…」换成可核对的回执。

Axis: tool-transparency

Basis:
direct: page.tsx 仅有通用 spinner；route.ts 服务端 tool 结果不进入客户端流 external: Cursor/Manus 活动面板；Perplexity 过程可见性

Rationale: Live Tools 是产品差异点，却在 UI 上被抹掉。用户感觉「太简单」，往往是因为看不到真实工作，只像套壳聊天。

Downsides: 需要改流协议或至少加阶段信号；过度暴露原始 JSON 会变吵——默认折叠。

示意：等待时间变成可审计的工具回执，而不是模糊转圈。

3. 答案结果卡片（Result cards in the thread）

ID 3 tool-transparency Confidence 84% Complexity Medium

Description: 把价格 / TVL / gas / repo stats 从散文与灰表升级为结构化卡片（数字、24h 变化、来源芯片）。路径 A：扩展 Markdown.tsx 对 GFM 表/链接做启发式包装（零协议改动）；路径 B：流式 typed parts（Vercel generative UI）。可与 #2 的来源芯片打通。

Axis: tool-transparency

Basis:
direct: 助手回复仅 Markdown 渲染 m.content；无 tool widget external: Vercel AI SDK generative UI；Messari Copilot 表/图/引用

Rationale: DeFi 答案是证据型数据。气泡里的 Markdown 墙让产品看起来像通用 LLM，而不是分析台。

Downsides: 启发式可能误伤普通表；typed parts 需要消息模型升级。

4. 品牌脊线 + 真玻璃感（Brand spine + real glass）

ID 4 visual-identity Confidence 90% Complexity Low

Description: 把 icon.svg 的 #2563EB → #7C3AED 提升为 --accent-start/end，只用于品牌标、发送键、焦点环、活动态——其余保持克制中性面（Phantom/Uniswap 式单强调色）。重写 .glass-panel：半透明 + blur + 轻微渐变描边，让 body 径向背景真正透出来；聊天列用更强阴影成为主舞台。换掉默认 Inter，选有性格的显示/正文字体对。

Axis: visual-identity

Basis:
direct: icon.svg 定义 defiGrad；globals.css glass-panel 为不透明白；UI 大量 flat blue-600 external: Phantom / Uniswap 单强调色；Aave Glass 深度材料

Rationale: 「不好看」很大程度是身份缺失：favicon 有品牌，页面像通用开发门户。这是纯视觉、低风险的立即提升。

Downsides: 过度渐变会落入 AI 紫蓝套路——强调色必须克制；字体加载需注意性能。

示意：品牌资产进入系统 token，材料有深度，强调色只出现在行动点。

5. 简报台，不是聊天气泡（Briefing desk）

ID 5 chat-surface Confidence 78% Complexity Medium

Description: 去掉左右气泡与 YOU/Bot 圆形头像戏法。用户提问为细查询条；助手回复为全宽「研究简报」面板（标题结论 + 展台式表格/代码/引用）。信息架构不变，但视觉从「玩具聊天」切到「分析台」。

Axis: chat-surface

Basis:
direct: page.tsx 气泡 max-w-[85%] + 角色色壳；助手已是密集 GFM external: Messari / Perplexity 文档式答案；新闻编辑室脚注节奏

Rationale: 气泡版式与 DeFi 表格/计划天然冲突；「太简单」常来自 iMessage 联想，而不是内容不足。

Downsides: 可能削弱熟悉的聊天心智；需要更强的排版层级以免变成白墙。

6. 全幅操作台 + 可折叠上下文（Operator console）

ID 6 layout-hierarchy Confidence 80% Complexity Medium–High

Description: 取消居中 max-w-[1200px] 双白卡片模板。顶栏变薄状态条；桌面默认聊天占 ≥70% 宽，侧栏收成 48px 图标轨、展开为抽屉；移动端侧栏改为 bottom sheet，默认聊天优先。去掉硬编码 calc(100vh-65px)，用真实 header 高度。

Axis: layout-hierarchy

Basis:
direct: header/main 均 max-w-[1200px]；lg:w-[320px] 固定吃掉聊天宽度；移动端 flex-col 侧栏在上 external: Bankr / Bloomberg 终端构图；Cursor 可折叠侧工件

Rationale: 「居中双卡片」是模板感的主因。操作台构图让后续结果卡、活动条有空间生长。

Downsides: 布局改动面大；全幅不等于堆仪表盘——仍要避免首屏杂讯。

示意：聊天是主台面；上下文是可展开的检查器，而不是对等的第二张卡片。

7. 一键发动 + 预装芯片（One-tap invoke + staging chips）

ID 7 chat-surface Confidence 86% Complexity Low

Description: 侧栏 / 空态点击不要只 setInput 后干等。默认直接提交 demoPrompt；或在输入框上方放「已武装：get_token_price」芯片（可关闭），避免整段提示词覆盖用户草稿。空态去掉与侧栏重复的三张提示卡，改成引导去点左侧工具/项目。

Axis: chat-surface

Basis:
direct: page.tsx 点击仅 setInput；空态三按钮与 repo demoPrompt 文案三重维护 reasoned: 「点了没反应」是移动端与新用户最容易感到「半成品」的摩擦

Rationale: 发现路径若半途而废，再漂亮的视觉也救不了「不好用→不好看」的整体印象。

Downsides: 自动发送可能让用户来不及改参数——长按编辑或芯片确认可缓解。
